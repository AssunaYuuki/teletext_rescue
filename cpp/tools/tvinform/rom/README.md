# ПЗУ приёмника «ТВ-Информ М3» (1997)

Источник дампов: red-innovations.su/index/photos_c/tvinform.html (tvinform_m3.zip), копия в Rus\tvinform.
Плата декодера «0311» (фото на том же сайте) — жёсткая логика ТТЛ: счётчики 74ALS161, регистры
КР1533ИР10 / К555ИР8, схемы чётности К155ИП2, шинные 74ALS245 и три ПЗУ К556РТ5 (d13 с меткой «1», «30»
и третья без метки). Дампов только два, какое из них какое на плате — не известно (вероятно, «128_1» = d13 «1»).
Схемы нет, поэтому назначение ПЗУ 556РТ5 ниже — выводы по содержимому.

## 556рт7а_tvinform_m3_yprvl.064 — 8051, управление («упрвл»), 2 КБ
Не разбирает VBI. Это контроллер тюнера и передней панели (листинг: tvinform_m3_8051.asm):
- 000B / 001B: прерывание таймера 1 (TH1:TL1 = DF72) — динамическая индикация: два знака 7-сегментного
  индикатора (38h, 39h) по очереди выводятся в защёлку `MOVX @R0` (адрес 0), разряды — P1.6 / P1.7.
  Таблица знаков 0297: C0 F9 A4 B0 99 92 82 F8 80 90 = «0»..«9» (общий анод, бит 0 = a … бит 6 = g).
  Служебные надписи (по сегментам):
  - 88 C1 = «AU» — канал 0: видеовход (AV, тумблер «ВИДЕО/ВЧ»);
  - C8 88 = «ПА» — нет ответа EEPROM (A0) по I²C: ошибка памяти каналов;
  - C6 86 = «CE» — нет ответа синтезатора (C6) по I²C;
  - C8 B0 = «П3» — не сошлась контрольная сумма ПЗУ («ПЗУ»);
  - BF BF = «--» — запись в память; C6 F0 — подстройка; FF FF — погашено (дежурный режим, PCON).
- 0183: клавиатура — P1.0..P1.3 (код 0F = ничего не нажато), обработка команд 0204: 0E/0D — канал ±, 0B/07 —
  P3.5 вкл/выкл, 03/05 — P3.4, 06/09/0A/0C — запись в память / подстройка.
- 032B..0396: программный I²C на P3.0 (SDA) / P3.1 (SCL):
  - A0/A1 — EEPROM 24Cxx: номер канала (30h) и подстройка (33h) по каждой ячейке памяти;
  - C6 — синтезатор частоты тюнера (TSA5512 / SP5055-подобный): 050E шлёт 5 байт: делитель (31h:32h),
    управляющий байт 8E и байт диапазона (02 / 04 / 01 по делителю — МВ-I / МВ-III / ДМВ).
- 043A: таблица делителей каналов ОИРТ, шаг 62.5 кГц, ПЧ изображения 38.0 МГц:
  057C = 1404 → 87.75 МГц = 49.75 + 38 (R1), 0614 → 97.25 = 59.25 + 38 (R2), 0734 → 115.25 (R3),
  07B4 → 123.25 (R4), 0834 → 131.25 (R5), 0D54 → 213.25 = 175.25 + 38 (R6) … и ДМВ 21–60.
- 02BA: контрольная сумма ПЗУ 0000..0688 сверяется с 3 байтами по 0689.
- Строка автора в ПЗУ: «IZOFATOV SERGEY NIKOLAEVICH 22.09.97» и телефоны (Москва).
- P3.3 — внешний вход (признак сигнала / режима), P3.7 — светодиод при канале 0, PCON = 1 — режим ожидания.

## 556рт5_52004.064 — 512 × 8
- D7 = 0 на адресах 48, 49, 98, 99, … 498, 499: каждые 50 адресов — сброс счётчика по модулю 50.
- D0..D3 меняются только на адресах 0..47: сначала 8 особых шагов, потом период 8 (D0 = 0 на 4-м и 5-м шаге
  каждой восьмёрки: 12, 13, 20, 21, … 44, 45) — разметка бит внутри байта на 6 байтах (48 шагов).
  Вывод: последовательностный автомат сборки байтов (стробы записи / сдвига) для слова из 6 байт.
  Для сравнения: на строке 19 ТВЦ / ОРТ (fТ1) после `55 55 27` и 2 байт идут 6 байт данных.

## 556рт5_128_1.064 — 512 × 8
- Активные (0) выходы только на трёх парах адресов: 111/112 (D1, D3, D4, D7), 150/151 (D0, D2, D7),
  211/212 (D1, D4, D7). Это дешифратор состояний счётчика: три момента (окна) с разными стробами.
  Если адрес — отсчёты тактом fТ2 (222 на строку), то 111 = середина строки (32 мкс), 150 = 43.2 мкс,
  211 = 60.8 мкс; если номер строки — строки 111, 150, 211 поля. Без схемы не определить.

## Итог
В ПЗУ нет ни формата пакетов, ни ключей — приёмник собирал и проверял данные аппаратно (ИП2, ИР10) и
отдавал их по RS-232 программе tv-inform.exe на ПК. Формат пакетов Norpak (ORT 1999 / 2002) восстановлен
по записям — см. src/tvinorpak.cpp и HANDOFF.md.
